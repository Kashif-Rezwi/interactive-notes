# Memory Curation Policy

**Adoption state:** Partially active — the promotion test, confidence levels, and conflict/decay rules are in force now (three memory items exist under `records/memory/`); the weekly-clustering and periodic-review ceremonies begin when memory volume justifies them.

## Promotion test

Promote a lesson only when it is: supported by linked evidence; specific enough to act on; general enough to recur; scoped to conditions where it is true; non-duplicative; safe to retain; and assigned an owner and review date.

Use the memory template to capture statement, context, evidence, confidence, tags, counterexamples, recommended action, and expiry. Low-confidence or single-run findings remain in episodic records until replicated.

## Confidence levels

| Level | Meaning | Use |
| --- | --- | --- |
| Established | Repeated evidence or approved decision; limitations known | Default guidance within scope |
| Supported | Strong evidence from one controlled or several consistent runs | Suggested with verification |
| Tentative | Plausible observation, insufficient replication | Experiment input only |
| Disputed | Credible conflicting evidence | Surface both sides; do not automate |
| Retired | No longer applicable or superseded | Preserve for history; exclude from retrieval |

## Conflict and decay

Do not merge contradictory lessons into vague advice. Link conflicts, identify different contexts, and create an experiment or decision-needed record. Memory items expire or require review when model behavior, benchmark, policy, domain standards, or workflow assumptions change. Supersession preserves the old item and names its replacement.

## Curation cadence

Perform run-level disposition at closure, weekly clustering of recurrent observations, periodic review of high-impact items, and release-time audit of memory used in production. Measure precision of retrieved memory: guidance that routinely harms or distracts work should be narrowed or retired.
