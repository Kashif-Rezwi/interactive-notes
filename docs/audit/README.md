## Why this category exists

The [repository map](../02-system/repository-map.md) requires justification for a new top-level documentation category. An end-to-end workflow audit evaluates the pipeline *across* product standards (01), system contracts (02), workflows (03), agents (04), prompts (05), evaluation (06), and records — it is not itself an evaluation policy (06), an operational playbook (09), or a governance rule (10), and placing it under any one of those would misstate its authority. Audits here are diagnostic records, not binding standards: they observe, classify evidence, and stop short of recommendations.
